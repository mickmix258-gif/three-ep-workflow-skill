# EP2 • CONTEXT SYSTEM: ระบบบริบทองค์กรแบบหลายชั้นที่ใช้ซ้ำได้

เป้าหมายของ EP2 คือการขจัดปัญหา "ต้องอธิบายธุรกิจใหม่ทุกครั้งที่เปิดห้องแชทใหม่" โดยการจัดโครงสร้าง Context ให้เป็นชั้น ๆ (Context Layering) ที่พร้อมเรียกใช้ซ้ำได้ตลอดเวลา

---

## 1. ปัญหาของ Context แบบกระจัดกระจาย

- ผู้ใช้ต้องพิมพ์ Background เดิมซ้ำ ๆ ทุกครั้ง
- คนในทีมเดียวกันสั่งงาน AI คนละแบบ ได้ผลลัพธ์คนละมาตรฐาน
- Context ที่ยาวเกินไปทำให้เปลือง Token และโมเดลหลงลืมข้อกำหนดสำคัญ

---

## 2. โครงสร้างบริบท 3 ระดับ (The 3-Tier Context Architecture)

```text
+---------------------------------------------------------------+
|  LEVEL 1: COMPANY STANDARD CONTEXT (ระดับองค์กร)              |
|  - ค่านิยมและวิสัยทัศน์ของบริษัท (Vision & Mission)            |
|  - โทนเสียงและการสื่อสารทางการ (Tone of Voice & Brand Identity)|
|  - กฎระเบียบความปลอดภัยและนโยบายความเป็นส่วนตัวของข้อมูล       |
+---------------------------------------------------------------+
                               │
                               ▼
+---------------------------------------------------------------+
|  LEVEL 2: TEAM / PROJECT DOMAIN (ระดับทีมและโปรเจกต์)         |
|  - วัตถุประสงค์ของโปรเจกต์และกลุ่มเป้าหมาย (Target Audience)  |
|  - ข้อมูลผลิตภัณฑ์ สเปกทางเทคนิค และ Baseline Metrics         |
|  - คลังคำศัพท์เฉพาะทาง (Glossary & Acronyms)                   |
+---------------------------------------------------------------+
                               │
                               ▼
+---------------------------------------------------------------+
|  LEVEL 3: TASK-SPECIFIC INPUT (ระดับโจทย์เฉพาะหน้า)          |
|  - ความต้องการของงานรอบนี้                                    |
|  - ไฟล์อินพุตเฉพาะกิจ                                         |
|  - ข้อจำกัดเรื่องเวลาและผู้รับมอบงาน                          |
+---------------------------------------------------------------+
```

---

## 3. การออกแบบ Skill ประจำทีม (Design Skill for Team)

เมื่อทีมค้นพบรูปแบบ Prompt หรือกระบวนการที่ให้ผลลัพธ์ยอดเยี่ยม (Winning Scaffold):
1. **บันทึกลงเป็น Playbook:** แปลงกระบวนการนั้นให้เป็นไฟล์ Markdown ในโฟลเดอร์ `.agents/skills/<team-skill>/SKILL.md`
2. **แชร์ผ่าน Version Control (VCS):** นำเข้า Git Repository เพื่อให้ทุกคนในทีมซิงค์ไปใช้งานได้เหมือนกัน
3. **เวอร์ชันและปรับปรุง:** บันทึกการเปลี่ยนแปลง (Versioning) เมื่อมีการอัปเดตเกณฑ์ Rubric หรือสเปกงาน
